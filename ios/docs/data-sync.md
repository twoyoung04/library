# iOS 本地存储与云同步规格

当前版本使用受系统保护的本机文件，将藏书与待同步操作原子写入。云端按页恢复整份书库，以服务端记录版本检查并发修改。以下 SwiftData 和增量游标是后续架构方案。

## 数据归属

本机书库使用 SwiftData 持久化，书单和搜索从本机读取。`UserDefaults` 保存界面偏好，Keychain 保存登录凭据。扫码、编辑和删除优先写入本机数据库。云同步只在用户登录并主动开启后运行。关闭同步后，用户还可以继续维护本机书库。[Apple SwiftData 文档](https://developer.apple.com/documentation/swiftdata/modelcontainer)

| 数据 | 归属及标识 |
| --- | --- |
| 公共书目 | 规范化 ISBN 对应的基础书目信息，由服务端查询与维护 |
| 私有书目 | 用户自己的书名修订、手工书目和自有资料，归属当前书库 |
| 实体副本 | 每册使用客户端生成的 UUID，保存位置、状态、备注和入藏日期。同一 ISBN 可有多册 |
| 标签及关联 | 归属当前书库，名称唯一性在书库内判断 |
| 同步记录 | 本地待提交操作、服务端记录版本、删除标记和每个账号的增量游标 |

无账号的本机书库与各账号书库有独立存储范围。服务端根据经过认证的账号推导数据归属，网页、移动接口和后台任务使用同一套权限约束。ISBN 查询可以复用公共缓存，查询请求只包含所需的书目标识。

## 写入、恢复与冲突

1. 本机修改与待同步操作在同一次数据库事务中提交。每个操作带唯一请求 ID、记录 UUID 和基础版本号。上传重试复用同一请求 ID，服务端返回已处理结果。
2. 按账号游标拉取远端变更。成功应用一批数据后保存新游标。遇到过期游标时执行完整对账，保留本地尚未提交的操作。
3. 不同字段的并行修改在可确认时合并。相同字段发生冲突时保留双方值，并向用户提供处理入口。删除用带版本的标记传播，旧设备的更新不得自动恢复该记录。
4. 网络失败保留队列并退避重试，设置页展示上次同步时间、待同步数量和手动重试。App 被关闭、账号切换或同步授权撤回时，按账号隔离队列，恢复时重新校验。

## 游客转账号与退出

首次开启同步时，先显示本机和目标账号的书库概况。用户确认后，以稳定 UUID 导入本机记录。账号书库里的同 ISBN 副本保留为不同实体，可能重复的记录可供用户核对。导入中断时继续同一批次，本机原始数据保留到导入完成并校验。换机登录后从账号恢复，再进行增量同步。

退出时提示尚有待同步记录，提供先同步或导出选项。退出后切回游客书库，账号书库与其队列保持隔离。账号删除流程应说明云端数据清理、本机副本的处理方式和备份保留周期。

## 旧数据迁移与验证

先确认原单人书库的目标账号。迁移脚本建立明确的旧记录 ID 映射，支持重复执行，分别核对书目、实体副本、标签和关键字段。生产变更前生成可恢复的备份。现有 iOS 缓存只可用于识别本机待同步录入，线上藏书以服务器数据为准，避免把已在云端的缓存再次导入。

验收至少覆盖两个账号的越权检查、导入中断重试、同 ISBN 多册、双设备同时修改和删除、退出后的本地隔离，以及从备份恢复。生产切换前在测试环境完成一次完整迁移演练并记录核对结果。
